# QA 0.4.0 — Magma by default

Primal now starts from Mycelium's own colour: Magma #E61924 on ink #0B0B0D and white #FFFFFF, taken from the brand book
(`mycelium-brand`, `src/styles.scss`). The model is unchanged: one primary, and every role, state and step derives from it, so
a project still replaces Magma by setting `--pr-primary`. Folio plan: `.folio/ledger.json`, release 0.4.0, decision 26. It
builds on 0.3.0 ([Mycelium-LLC/primal-ui#4](https://github.com/Mycelium-LLC/primal-ui/pull/4)); merge that first and this
release's diff is only 0.4.0.

## Run it from a fresh clone

Needs Node 24 (`.nvmrc`).

```bash
git clone -b release/0.4.0 https://github.com/Mycelium-LLC/primal-ui.git primal-qa && cd primal-qa
npm ci
npm run check:folio
npm run check:tokens
npm run build
npx ng serve showcase  # http://localhost:6840 — Foundation › Colour first
```

Failing looks like: a ✖ line from any check, an `✘ [ERROR]` from the build, a primary button whose text is not white in
light or black in dark, or a page that scrolls sideways at phone width.

## What to check, and what was checked

Pickers, Select, Validation with its messages showing, Example forms, Text, Media) at desk width in light and dark, with
screenshots sent to Niko; the Colour page at 375px (no sideways scroll). The browser's computed colours were compared with
the colour model's own, role by role: they match exactly.
