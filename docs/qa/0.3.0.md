# QA 0.3.0 — Fields that never leave you guessing

Every native form control has one field contract: a label, a description when it needs one, "Optional" where it can be
left empty, the browser's own control, and a message that says what to type. Folio plan: `.folio/ledger.json`, release
0.3.0. It builds on 0.1.0 and 0.2.0 ([#1](https://github.com/Mycelium-LLC/primal-ui/pull/1),
[#2](https://github.com/Mycelium-LLC/primal-ui/pull/2)); merge those first and this release's diff is only 0.3.0.

## Run it from a fresh clone

Needs Node 24 (`.nvmrc`).

```bash
git clone -b release/0.3.0 https://github.com/Mycelium-LLC/primal-ui.git primal-qa && cd primal-qa
npm ci
npm run check:folio
npm run check:tokens
npm run build
npx ng serve showcase  # http://localhost:6840 — the Forms section
```

Failing looks like: a ✖ line from any check, an `✘ [ERROR]` from the build, a message that appears while you're still on
your first try, or a page that scrolls sideways at phone width.

## What to check, and what was checked

Checked by Claude in the built-in browser on 2026-10-20: every Forms page by eye at desk width; Choices and Select in dark
and right to left; all seven at 375px (no sideways page scroll). The validation journey was driven end to end.

| # | Element, state or journey | Folio requirement | Result |
|---|---|---|---|
| 1 | Text fields: every field has a visible label tied to its control; descriptions read out with it (`aria-describedby`); "Optional" on what can be left empty, never on a choice, a slider or a colour | `primal/fields/every-field-has-a-visible-label-an-optional-description-a` | ✓ |
| 2 | States: read-only (a quiet edge, full-strength text), disabled (sunken, muted, its label muted too, with the reason in its description), invalid (danger edge and message) | same | ✓ |
| 3 | Every native type is covered and stays native: text, email, password, tel, url, search, number, text area, date, time, datetime-local, month, week, range, colour, file, select (single, grouped, multiple), suggestions (datalist), checkbox, radio, switch | `primal/fields/each-native-field-type-the-text-kinds-number-date-and-time` | ✓ |
| 4 | Radio groups: one legend, one message for the group; arrow keys move between options; choosing one clears the group's message | `primal/fields/related-fields-group-under-a-shared-legend-and-a-radio-group` | ✓ |
| 5 | Switches say what they change ("Email me a weekly summary"), never "On" or "Enabled" | `primal/fields/a-switch-or-toggle-says-what-it-changes-in-words-rather-than` | ✓ |
| 6 | Validation journey: submit empty, and six messages appear under their fields, focus goes to the first, every control is `aria-invalid`; fix them one by one and each clears at once; a valid submit says so; Reset starts over with no messages | `primal/validation/a-field-s-error-says-what-happened-and-what-to-type-sits` | ✓ |
| 7 | Messages say what to type: "Enter your email.", "Enter 18 or more.", "Use at least 12 characters.", a pattern's own title; an outside error ("That username is taken…") wins | same | ✓ |
| 8 | Example forms: sign-in (a submission), profile (a builder), settings (switches and radios that take effect at once, no Save), with no styles of their own | `primal/forms/a-developer-builds-a-sign-in-a-profile-edit-and-a-settings` | ✓ |
| 9 | Each page shows the Angular markup and the same thing in plain HTML | decision 24 | ✓ |
| 10 | Coverage page: input, select, textarea, label, fieldset, legend and form are now "enhanced" in 0.3.0; output, progress and meter "styled" | `primal/coverage/every-rendering-element-of-the-html-standard-has-a-recorded` | ✓ |

## Not in this release

- Messages are in English. Another language means providing `PRIMAL_MESSAGES`; Hebrew isn't written yet.
- Buttons keep the early base (a submit wears the primary); the action primitives are 0.4.0.
- The showcase is not deployed anywhere yet (no hosting chosen).
