# QA 0.2.0 — Plain HTML reads right

Every element of the HTML standard has a decided outcome, and plain HTML or Markdown reads well with no classes: text,
lists, quotes, code, tables, media and page landmarks. Folio plan: `.folio/ledger.json`, release 0.2.0. It builds on
0.1.0 ([Mycelium-LLC/primal-ui#1](https://github.com/Mycelium-LLC/primal-ui/pull/1)); if 0.1.0 is merged first, this
release's diff is only 0.2.0.

## Run it from a fresh clone

Needs Node 24 (`.nvmrc`).

```bash
git clone -b release/0.2.0 https://github.com/Mycelium-LLC/primal-ui.git primal-qa && cd primal-qa
npm ci
npm run check:folio    # ✔ ledger ok
npm run check:tokens   # ✔ tokens up to date / contrast / no literal values
npm run build          # ✔ Built primal-angular, then "Application bundle generation complete"
npx ng serve showcase  # http://localhost:6840 — the Native HTML section
```

Failing looks like: a ✖ line from any check, an `✘ [ERROR]` from the build, or a page that scrolls sideways at phone width.

## What to check, and what was checked

Checked by eye by Claude in the built-in browser on 2026-10-20: every Native HTML page at desk width, at 375px and in dark;
right to left on Text and Quotes and code. Every page in the showcase was measured for sideways page scroll at 375px (none).

| 2 | Native controls are kept wherever they serve better (date inputs, option lists, audio and video players, captions as tracks), each with its reason | `primal/coverage/native-behaviour-is-kept-wherever-it-serves-the-person` | ✓ |
