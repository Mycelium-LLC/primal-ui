# QA 1.0.0 — Open to everyone

Ready for QA. Niko delegated every 1.0.0 decision on 2026-11-03 ("u decide all"); they're decisions 35 to 41 in
`.folio/ledger.json`. 1.0.0 is Primal's first public release: the packages on npm, the repository public, and the landing
page, showcase and acceptance app at primal.myceliumllc.dev.

## How QA runs

QA care is **Forensic** (the release goes public and can't be taken back). A session that didn't build it runs the
`qa-report` skill on the exact head of `release/1.0.0`, from a fresh clone, as three strangers. It records every bug,
confusion and friction, with the step it happened at.

### Journey 1: a newcomer on the landing page

1. Open the preview of primal.myceliumllc.dev (the `prerelease` channel, linked in the PR). Answer in a sentence: what is
   Primal, and is it for me? Then judge whether the page said it.
2. Use the page's own colour picker, right to left and dark. Everything on the page must follow.
3. Follow **Install Primal**, then **Fork Primal**. Each must reach a working install or a working copy in two steps.
4. At phone and desk width, in Chrome, Safari and Firefox.

### Journey 2: install Primal into a new project

1. Fresh clone, `npm ci`, `npm run pack` (Node 24): four `@mycelium-llc` tarballs in `dist/packs/`.
2. Copy `starter/` out of the clone, install the four tarballs instead of the registry versions, and follow
   `starter/README.md`. It must build and run, and its first screen must work: empty, create, delete with Undo.
3. Then a new `npx @angular/cli@22 new` project, set up from the README's **Install Primal** steps alone.

### Journey 3: fork Primal into your own design system

Follow `docs/fork.md` from step 1: your colours (including an off-white and a lighter black, inside the stated range), your
type, your name, one component of your own with its contract, and `primal-contracts-check`. Report anything that forced an
edit inside a Primal component.

### Also check

- The acceptance app at `/demo/`: every journey in it, and that nothing in it needed a behaviour Primal lacks.
- `npm run check:tokens` sweeps 27 blacks and whites; try your own outside it on the Colour page and see the misses shown.
- The publish and deploy workflows read right (they only run on a tag).
- Nothing in the repository should be private: no secrets (gitleaks on the full history is clean), no personal data.

## Known before QA

- **VoiceOver wasn't run.** axe-core is clean, and keyboard journeys pass, but no one has listened to it yet.
- **In Safari, a mouse click doesn't focus a button**, so focus-after-delete only applies to keyboard use there, as Safari
  intends. By keyboard it lands on the next row or the heading.
- **Commit authors** show Niko's address on 82 commits once the repository is public. History isn't rewritten for it.
- **Publishing needs Niko once:** an npm account owning the `mycelium-llc` organisation, and its token as the repository's
  `NPM_TOKEN` secret.
- **The Primal link colour is a shade deeper** (decision 41): Magma as text went from TEXT_CAP 0.14 to 0.11.
