## How QA runs

QA care **Standard**. A session that didn't build it runs `qa-report` on the exact head of `release/1.0.1`, from a fresh clone.

1. `npm ci`, `check:folio`, `check:tokens`, `check:contracts`, `npm test`, `npm run build`, `npm run build:site`, `npm run pack`, `node scripts/check-app.mjs starter`.
2. In each of `packages/tokens`, `packages/css`, `packages/contracts` and `dist/primal-angular`: `npm publish --dry-run --access public`. Judge the tarball as npm would show it: nothing missing (LICENSE, README, the CSS, fonts and OFL, contracts and schema, the Angular bundle and types), nothing that shouldn't ship (build scripts, specs, sources of the adapter).
3. Read each `package.json` as npmjs.com renders it: description, keywords, homepage `https://primal.myceliumllc.dev`, repository with its directory, bugs, license (MIT; css `(MIT AND OFL-1.1)`), author `Mycelium LLC <hello@myceliumllc.dev>`, `files`, `exports`, `sideEffects`, peer dependencies.
4. Read each package README as a stranger on npmjs.com: the Primal mark at the top from an absolute https URL (it is served from `dist/site/brand/primal-mark.png`, live once the tag deploys), install, the 30-second example (does it work as written?), links back. Try the examples in a fresh `ng new` project with the packed tarballs, including the `exports` paths (`@mycelium-llc/primal-css/primal.css`, `@mycelium-llc/primal-tokens/colour-model`).
5. `.github/workflows/publish.yml` (npm Trusted Publishing: `id-token: write`, npm ≥ 11.5.1, no token, provenance; skips a package not on npm yet and a version already there) and `docs/publishing.md` (the first manual publish, the trusted-publisher settings per package). Would a tag publish the right four folders, and only those?

Publishing itself waits on the npm account (`myceliumllc`), its organisation (`mycelium-llc`) and the first manual publish; that is not a defect.
