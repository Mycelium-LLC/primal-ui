## How QA runs

QA care **Standard**. A session that didn't build it runs `qa-report` on the exact head of `release/1.0.1`, from a fresh clone.

1. `npm ci`, the checks (`check:folio`, `check:tokens`, `check:contracts`), `npm test`, `npm run build`, `npm run build:site`, `npm run pack`, `node scripts/check-app.mjs starter`.
2. Read `.github/workflows/publish-github-packages.yml` as the reviewer of a publish: it runs on a GitHub release (or by hand), uses only the workflow's `GITHUB_TOKEN` with `packages: write`, checks the release tag against the four versions, runs the checks and the build, publishes `packages/tokens`, `packages/css`, `packages/contracts` and `dist/primal-angular` to `https://npm.pkg.github.com`, skips a version already there, and strips npm provenance (npmjs only) before publishing. `publish.yml` (npmjs) only runs by hand.
3. Read every install instruction as a stranger: the README, `packages/*/README.md`, the showcase's Getting started (`/showcase/start`), the landing page's Install Primal, `starter/README.md` and `starter/.npmrc`. Each must say: the `.npmrc` lines (`@mycelium-llc:registry=https://npm.pkg.github.com` and `//npm.pkg.github.com/:_authToken=${GITHUB_TOKEN}`), that GitHub Packages needs a token with `read:packages` even for a public package, then `npm install …`.
4. Versions: root, the four packages, the CHANGELOG, the landing page and showcase (`/version.json` after build) all say 1.0.1.

Installing from GitHub Packages itself can only be checked after the release publishes; the release session does that (below).
