# QA 0.9.0 — Every element keeps its promise

Ready for QA (Niko, 2026-11-02: "lets prepare this for the qa i wanted"). Folio plan: `.folio/ledger.json`. `release/0.9.0` holds
every release not yet shipped, 0.3.0 to 0.9.0, so this one QA covers them all; when it passes, 0.9.0 ships once (the newest,
containing the others).

## How QA runs (decision 29)

A session that didn't build Primal runs the `qa-report` skill on the exact head of `release/0.9.0`, from a fresh clone, and
walks two journeys from nothing. Record every bug, confusion and friction on the way, with the step it happened at.

### Journey 1: use Primal in a new Angular project

1. Fresh clone of `release/0.9.0`; `npm ci`; `npm run pack` (needs Node 24). Expect three files in `dist/packs/`.
2. Outside the clone, `npx @angular/cli@22 new` a project (CSS, no SSR). Install the three tarballs.
3. Follow the showcase's Getting started page, and nothing else, to load the styles and the providers.
4. Build one real screen with Primal's parts: a sign-in form, a list of things with an empty state, a Delete with Undo, a
   dialog, a table that sorts. Use the contract catalog (`/contracts/catalog`) to find what to use and how.
5. `ng build` and `ng serve`; check it by eye in light and dark, left to right and right to left, desk and phone width,
   and by keyboard alone.
6. Report: what broke, what the docs didn't say, what was harder than it should be.

### Journey 2: build your own design system on Primal

1. In the same project, make a brand of your own: pick a black, a white, a primary and a harmony on the showcase's Colour
   page, and load the theme file it writes after Primal.
2. Override other tokens the way Themes says (a radius, a font, a gap); never edit a component.
3. Add one component of your own to the system, built only from Primal's tokens and parts, and write its contract the way
   `packages/contracts/schema.json` asks.
4. Check that every screen from Journey 1 now wears the new brand, still passes contrast, and still works in dark and right
   to left.
5. Report: how easy it was, what had to be worked around, and anything that forced you to edit Primal itself.

### Already known before QA

- Page transitions could not finish in the hidden browser pane used while building, so route changes were checked with
  transitions switched off (0.8.0, and the shell's scroll checks below). QA in a visible browser settles it.
- The packages are not published; the npm scope is a 1.0.0 question.

## What this release adds

- `packages/contracts`: `schema.json`, one contract per component in `src/`, and `contracts.json` built from them.
- `npm run check:contracts` (also in `npm run build` and CI): fails when a component has no contract or an incomplete one.
- Contracts › Contract catalog: every contract by layer, and a generated page per contract (`/contracts/catalog/<id>`).

model hold for any black and white is a pending requirement for 1.0.0.
